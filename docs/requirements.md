# Техническое задание

**Проект:** iOS Presentation Bot  
**Версия:** 0.1 (проект, не утверждён полностью)  
**Дата:** 11.10.2026  
**Мероприятие:** выступление по архитектуре iOS, 21.10.2026

## 1. Цель и границы

Небольшой интерактивный опрос перед выступлением. Участники голосуют в Telegram, а на проекторе динамически отображаются агрегированные результаты. Автор выступления управляет голосованием из Telegram.

Проект **не** является системой официального голосования или репрезентативного социологического исследования. Срез отражает только ответы участников конкретного семинара.

В первой версии нет необходимости в регистрации через сайт, сложной аналитике, многопользовательском администрировании или связи с учебной организацией `rosbiotech-studies`.

## 2. Роли

- **Участник** — открывает бота по QR-коду, отдаёт/меняет один голос в активной сессии, получает подтверждение и после завершения результаты.
- **Ведущий** — единственный администратор, может начать/завершить сессию, посмотреть статус и начать новый тестовый раунд.
- **Зритель экрана** — видит только агрегированные данные без личной информации.

## 3. Основной сценарий

1. Ведущий открывает слайд с QR-кодом на Telegram deep link.
2. Участник запускает бота командой `/start`; до открытия голосования видит состояние ожидания.
3. Ведущий запускает новую сессию через административную кнопку.
4. Бот спрашивает: **«Какая ОС установлена на твоём основном смартфоне?»**
5. Варианты: **iOS**, **Android**, **Другая ОС**.
6. При выборе голос сохраняется атомарно; бот подтверждает запись.
7. До закрытия сессии участник может **изменить** ответ, но не создать второй голос.
8. Открытая страница результатов показывает две крупные анимированные колонки iOS/Android, отдельное число для «Другой ОС», общее число голосов и проценты от *всех* голосов.
9. Обновления поступают автоматически; после закрытия ведущим отображается итоговое состояние.
10. Бот рассылает участникам, которые его запускали и участвовали в текущем раунде, итоговую сводку. Не доставленные из-за блокировки бота/ошибок Telegram сообщения не блокируют завершение раунда.

## 4. Жизненный цикл опроса

Состояния: `WAITING` (сессия создана, не открыта), `OPEN` (приём голосов), `CLOSED` (зафиксированы результаты).

- Ровно **одна** сессия может принимать голоса одновременно.
- Повторные административные действия не должны случайно начинать второй активный раунд или рассылать итоги дважды.
- Завершение требует подтверждения в интерфейсе ведущего.
- Новый раунд — новая запись сессии; предыдущие данные не перезаписываются.
- После закрытия голос в этой сессии нельзя изменить.
- До старта, после закрытия и при отсутствии сессии публичная страница показывает понятное состояние, а не техническую ошибку.

## 5. Пользовательский интерфейс

### Telegram

- Кнопки выбора — inline-кнопки.
- Сообщения краткие и понятные, без технических терминов.
- Ошибка или устаревшая inline-кнопка приводит к объяснению текущего состояния, не к сбою.
- Команды/кнопки управления доступны только администратору по числовому Telegram user ID из конфигурации.
- Чужие попытки выполнить административную операцию отклоняются на стороне сервера.

### Экран результатов

- Ориентация **16:9**, полноэкранная работа в браузере.
- Два хорошо различимых столбца, подписи и численные значения, адаптация к большому проектору.
- Одинаковая вертикальная шкала обеих колонок; изменение масштаба не должно искажать сравнение.
- Анимированный рост голосов, без мигания всего экрана.
- Индикатор статуса соединения и сохранение последних известных данных при обрыве.
- В режиме `CLOSED` — явная надпись «Голосование завершено».
- Без фамилий, имён, Telegram ID и других идентификаторов участников.

## 6. Нефункциональные требования

- **Надёжность:** голоса и статусы переживают перезапуск бота, API и VPS.
- **Целостность:** уникальность `(session_id, telegram_user_id)`; транзакционные операции и корректный подсчёт.
- **Отклик:** при нормальной связи результат должен появляться на экране ориентировочно за 1–2 секунды; это целевой показатель, не гарантия внешней сети Telegram.
- **Нагрузка:** корректная работа с минимум 100 участниками за короткий интервал (критерии теста определяются в `testing.md`).
- **Безопасность:** HTTP-интерфейс только для чтения результатов; административные операции не публикуются в открытом API; токен бота и конфигурация — вне Git.
- **Приватность:** хранить минимум данных. Username, номер телефона и ФИО не требуются. Уведомить участников о факте использования их Telegram ID для недопущения дублей и рассылки результата. После события предусмотреть удаление идентификаторов или всей тестовой/боевой базы по решению владельца.
- **Доступность:** страница работает на обычном браузере без установки надстроек PowerPoint. При сбоях доступен статичный резервный экран.

## 7. Критерии приёмки MVP

- Один участник не может увеличить счётчик повторным нажатием или изменением ответа.
- Начало, закрытие и повторное тестовое голосование работают без потери истории.
- Непрерывные обновления происходят без перезагрузки страницы.
- Клиент после потери связи восстанавливает актуальную статистику.
- На экране нет индивидуальных пользовательских данных.
- Перезапуск процессов не стирает голоса.
- Сервис доступен из отдельной внешней сети по согласованному URL.
- Показ в PowerPoint имеет как минимум один надёжный способ открыть страницу результатов.

## 8. Открытые решения

Это **не подтверждённые требования**, а вопросы до реализации:

1. Второй вопрос о критериях выбора смартфона — добавлять ли после рабочего MVP?
2. Нужен ли режим голосования в браузере, если у участника недоступен Telegram?
3. Нужна ли анонимная публикация итогов по постоянному адресу после выступления?
4. Требуется ли встроенная веб-страница в слайде PowerPoint или достаточно гиперссылки?

Эти решения не должны мешать созданию базового одновопросного голосования.
