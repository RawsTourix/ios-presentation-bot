# План тестирования и приёмки

**Статус:** план; реальные тесты ещё не выполнялись.

## 1. Основной маршрут проверки

1. Запустить bot/web в тестовом окружении и открыть страницу `/screen`.
2. Войти владельцем, начать сессию и открыть Telegram-бота с двух разных аккаунтов.
3. Проголосовать за iOS и Android; убедиться, что столбцы растут и `total = 2`.
4. Повторно нажать свой вариант, затем сменить его; проверить, что `total` не увеличился, а категория изменена.
5. Подать третий голос «Другая ОС»; проверить абсолютные числа и проценты от **трёх** голосов.
6. Завершить голосование с подтверждением; проверить итоговый экран и уведомления участников.
7. Попробовать проголосовать после закрытия, повторно завершить тот же раунд, создать новый; история предыдущего раунда должна остаться неизменной.

## 2. Функциональные тесты

| ID | Проверка | Ожидаемый результат |
|---|---|---|
| F-01 | `/start` до открытия голосования | Понятное сообщение ожидания |
| F-02 | Голос в состоянии `OPEN` | Голос записан, счётчик увеличился на 1 |
| F-03 | Повторная кнопка выбора | Дубль не создаётся |
| F-04 | Изменение ответа | Старый выбор заменён; общее число не изменилось |
| F-05 | Две параллельные команды одного участника | В базе один действующий голос |
| F-06 | Одновременные голоса разных участников | Оба учтены |
| F-07 | Старая inline-кнопка после закрытия | Голос не меняется |
| F-08 | Не-администратор нажимает admin callback | Отказ, состояние опроса неизменно |
| F-09 | Закрытие без подтверждения | Опрос продолжает работать |
| F-10 | Повторное закрытие | Без повторного изменения/дублирования уведомлений |
| F-11 | Создание нового раунда | Чистый новый подсчёт, старая история сохранена |
| F-12 | «Другая ОС» | Голос учтён в общем числе и процентах |
| F-13 | 0 голосов | Нет деления на ноль или ошибок интерфейса |
| F-14 | Недоставляемое уведомление | Завершение не падает, ошибка доставки записана |

## 4. Долговечность и целостность

- Перезапустить бот в середине сессии: `status` и голоса сохранены.
- Перезапустить FastAPI: данные прежние, клиенты переподключаются.
- Перезапустить VPS: systemd восстанавливает службы, данные в БД не теряются.
- Имитировать два одновременных открытия новой сессии администратором: не возникают две `OPEN` сессии.
- Проверить конкурентные транзакции и уникальный индекс `(session_id, telegram_user_id)`.
- Убедиться, что отменённый тестовый раунд не влияет на подготовленный боевой.

## 5. Нагрузочный прогон

Сымитировать не менее **100 уникальных голосов** за короткий интервал, включая повторные вызовы и изменения ответов. Критерии: корректный итоговый подсчёт, отсутствие повреждения SQLite и необработанных исключений, работоспособный API и SSE.

Зафиксировать измеренные задержки появления голоса на экране (ориентир **1–2 секунды** при нормальной сети), частоту ошибок и фактическую конфигурацию VPS. Не выдавать ожидаемые показатели за измеренные.

## 6. Предварительная репетиция перед 21 октября

- Проверен ли веб-адрес с **другой сети**, а не только на VPS?
- Действителен ли TLS-сертификат и не истечёт ли он во время показа?
- Открывается ли сайт по гиперссылке из PPTX и по файлу `.url`?
- Удобно ли читать график с задних рядов на проекторе?
- Доступен ли Telegram аудитории?
- У ведущего работает admin-бот с мобильного интернета?
- Работает ли резервный статичный слайд?
- Тестовые сессии не перепутаны с боевой?

## 7. Отчёт о тестировании

После выполнения тестов зафиксировать отдельно: дату, ветку/commit, версии Python и зависимостей, характеристики среды, пройденные и непройденные сценарии, известные проблемы и решение о готовности к выступлению.

Пока здесь **нет** записей «passed»: это только план тестирования.
