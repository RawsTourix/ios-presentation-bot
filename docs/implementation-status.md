# Реализация: этап 1 — Telegram + SQLite

**Дата локальной проверки:** 12.10.2026  
**Ветка:** `feat/polling-mvp`  
**Статус:** реализовано ядро MVP; ещё не развёрнуто и не проверено с Telegram API.

## Что уже реализовано

- Сессии опроса `OPEN` и `CLOSED`; состояние `WAITING` возвращается при отсутствии сессии.
- Один действующий ответ на Telegram-аккаунт в рамках сессии, смена ответа через UPSERT.
- Устаревшие кнопки предыдущих сессий не могут изменить текущие результаты.
- SQLite WAL, транзакции `BEGIN IMMEDIATE`, контроль уникальности и источник агрегированной статистики.
- Команды `/start` и `/admin`, inline-кнопки, проверка Telegram ID ведущего.
- Подтверждение закрытия конкретной сессии; защита от старых кнопок администратора.
- Очередь уведомлений об итогах на основе участвовавших в сессии аккаунтов.
- Веточная CI-проверка: компиляция Python, импорт модуля Telegram-бота и тесты SQLite.

## Известные ограничения и долги

1. Рассылка итогов осуществляется best-effort. Записи, оставшиеся в состоянии `sending` из-за аварийной остановки, не восстанавливаются автоматически; ошибки переводятся в `failed`, автоматический повтор пока отсутствует. Требуется доработка надёжного восстановления с учётом риска повторной отправки.
2. В текущем этапе нет FastAPI, SSE и веб-страницы диаграммы.
3. Нет испытаний на настоящем Telegram-боте или университете.
4. Нет production-развёртывания, HTTPS, веб-публикации или PowerPoint-интеграции.
5. Нет проверки UX на разных клиентах Telegram.
