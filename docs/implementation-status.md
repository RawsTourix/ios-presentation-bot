# Статус реализации

**Дата обновления:** 12.10.2026  
**Ветка:** `feat/polling-mvp` · **PR #1 (Draft)**  
**Статус:** код этапов 1–2 создан и проверяется в GitHub Actions. Реальный Telegram-прогон, внешний HTTPS и PowerPoint ещё не проверены.

## Этап 1 — Telegram и SQLite

Реализованы сессии голосования, один действующий голос на аккаунт в рамках сессии, изменение ответа, защита от устаревших кнопок, администраторские команды, закрытие с подтверждением, агрегаты и учёт отправок итогов. Транзакции SQLite и режим WAL защищают целостность голосов.

## Этап 2 — FastAPI и экран результатов

Добавлены:

- `ios_poll/web.py`: фабрика FastAPI-приложения, инициализация общей SQLite-базы при старте, read-only API;
- `/screen`: публичная страница результатов для проектора;
- `/api/poll`, `/api/results`: текущий статус, сессия, агрегаты (без Telegram ID);
- `/api/events`: Server-Sent Events с первичным snapshot, обновлениями на каждое изменение версии, событием закрытия, heartbeat и проверкой отключения клиента;
- `/health`: чтение базы и простая проверка доступности;
- статические HTML/CSS/JavaScript: две анимированные колонки, шкала голосов, проценты, количество участников, отдельная категория «Другая ОС», индикатор связи;
- EventSource с автоматическим reconnect и резервным периодическим GET;
- проверка REST-эндпоинтов, выдачи ресурсов, приватности агрегатов, SSE-событий и heartbeat в `tests/test_web.py`.

### Обоснование изменения технологии графика

Первоначально планировали Chart.js. Для двух вертикальных столбцов реализован **нативный CSS/JavaScript**: без внешней библиотеки и CDN; рост контролируется абсолютным числом голосов при единой шкале (её верхняя граница может только увеличиваться в пределах сессии). Таким образом сохраняются требуемые анимации и независимость от сторонних сайтов во время семинара.

### Запуск на локальной машине

После установки зависимостей из `pyproject.toml`:

```bash
# Terminal 1; BOT_TOKEN и ADMIN_TELEGRAM_ID должны быть в окружении
python -m ios_poll.bot

# Terminal 2; обязательно одинаковый DATABASE_PATH
python -m uvicorn ios_poll.web:app --host 127.0.0.1 --port 8765
```

Открыть `http://127.0.0.1:8765/screen`. Локальный адрес не предназначен для доступа аудитории; публичный адрес появится только после настройки обратного прокси.

## Проверки и пределы подтверждения

GitHub Actions проверяет Python 3.11, установку проекта, компиляцию, импорт Telegram-обработчиков, тесты pytest и синтаксис браузерного JavaScript.

Для этапа 1 проверены 8 тестов SQLite, включая 100 конкурентных голосов, сохранность и защиту от повторов. Для этапа 2 добавлены 3 теста HTTP/SSE. Результаты **последнего** запуска CI нужно проверять по GitHub Actions; наличие теста в коде не означает его успешное прохождение.

Пока **не подтверждены**: реальные Telegram updates, отправка сообщений ботом пользователям, визуальная проверка на проекторе, SSE через внешний reverse proxy, HTTPS по публичному IP, интеграция с PowerPoint и работа при отключении интернета во время демонстрации.

## Известные ограничения

1. Рассылка результатов — best-effort. При аварийном завершении записи в статусе `sending` автоматически не возобновляются; нужна политика повторов, не допускающая массовой дублирующей рассылки.
2. Сейчас нет production-конфигурации systemd/reverse proxy, публичного URL и выпуска IP TLS-сертификата.
3. Нет дополнительного вопроса и браузерного голосования: оба пункта остаются открытыми решениями.
4. `WAITING` — публичное состояние при отсутствии сессии; хранение подготовленной, но ещё не открытой сессии не реализовано.
5. Размер аудитории и реальная доступность Telegram должны быть проверены отдельно.
